# 调研记录：单一横版平台游戏模式

## 决策 1：不能只改 Renderer 文案，必须锁定 Core 分类结果

- **决策**：对新固定模式项目，让 `classify_game_type` 确定性选择 `platformer` 并跳过分类模型请求。
- **原因**：当前新建弹窗本来就没有类型、引擎或目标选择；实际的五种玩法选择发生在 Agent 启动后的 Core 分类工具。如果只改首页和示例，用户输入“塔防”仍可能复制 `tower_defense` 模板，产品声明会与实际行为冲突。
- **否决方案**：仅更换示例 Prompt 或追加弱提示不能构成确定性约束；直接删除其它 archetype 会破坏旧项目、CLI 使用方和大量现有模板契约。

## 决策 2：新项目使用可选产品模式标记，缺失表示旧项目

- **决策**：`ProjectRecord` 增加一个可选的固定产品模式标记；`CreateProjectInput` 不包含该字段，所有新记录由 Main 固定写入。旧记录缺失标记时按 legacy 处理，并保持序列化内容不变。
- **原因**：固定约束只能作用于更新后创建的项目，否则用户已有的俯视、塔防、网格和 UI 项目在续跑时会被错误转换。可选字段无需全量改写旧 `state.json`，也不会让 Renderer 获得模式选择权。
- **否决方案**：把模式设为必填并在启动时迁移所有记录会增加 StateStore schema 与失败恢复风险；完全不存标记则无法可靠区分新旧项目。

## 决策 3：通过受控子进程环境传递固定 archetype

- **决策**：AgentRunner 只为固定项目设置精确的内部环境值 `platformer`；Core 只识别该单值，其它值不触发固定路径。
- **原因**：desktop 与 core 是独立 workspace，环境值已经用于模板和文档目录传递，且仅对子进程生效。该方案不新增 IPC、不让 Renderer 传命令，也避免 Core 反向依赖 desktop。
- **否决方案**：新增 CLI 公共参数会扩大外部 API 和参数校验范围；依靠项目文件读取会把桌面私有元数据耦合进通用 Core 工具。

## 决策 4：固定项目暂不加载用户扩展，旧项目保持原行为

- **决策**：固定产品模式不启用已有用户 Skills，也不把已保存 MCP Server 注入 Runtime；旧项目继续使用原有扩展行为。配置和凭据仍原样保存。
- **原因**：Unity、Godot、Blender 或自定义工具可能绕过固定产品边界。当前目标模式依靠内置 Core 工具即可完成制作，后续 AI 试玩将以受控能力重新引入。
- **否决方案**：按名称过滤“引擎类 MCP”无法可靠识别用户自定义 Server；删除配置违反本地数据和兼容原则。

## 决策 5：隐藏外部游戏引擎入口，保留 Web 构建运行环境

- **决策**：从主导航隐藏插件入口；设置中的依赖页收敛为 Node.js/npm 构建运行环境入口，隐藏 Unity、Godot、Blender 和与固定模式无关的工具；保留组件、Main 服务、配置、凭据、模板和测试代码。
- **原因**：固定 Phaser Web 项目仍依赖 Node.js/npm 完成构建与故障恢复，因此不能把运行环境入口一并隐藏。这仍是可回退的产品收敛，也保留旧项目兼容能力。深入删除和设置页重组属于后续桌面精简步骤。
- **否决方案**：本阶段物理删除会把 UI 收敛扩大为数据迁移、运行时裁剪和安装包兼容工程。

## 决策 6：复用现有 Web 预览安全边界

- **决策**：继续由 Main 在 `127.0.0.1` 随机端口服务项目内 `dist/index.html`，由 sandboxed iframe 试玩；只调整用户文案以明确这是 Web 浏览器预览。
- **原因**：现有实现已有目录包含、符号链接、方法、MIME、SPA fallback 和安全响应头测试，正好符合目标。
- **否决方案**：改为系统 Chrome/Safari 会新增外部 URL 打开 API 和本地 HTTP 白名单，不是本步骤所需。

## 决策 7：用聚焦行为测试加源码级 UI 契约，不新增测试框架

- **决策**：为 ProjectManager、AgentRunner 策略和 Core 固定分类增加行为测试；Renderer 沿用仓库现有的源码契约测试方式，另做一次真实 Electron 界面验收。
- **原因**：当前 desktop 没有 jsdom/happy-dom 或 React Testing Library，引入整套 UI 测试依赖会扩大范围。关键安全行为可以在 Main/Core 确定性验证，UI 可见面由契约和实机共同覆盖。
- **否决方案**：只做截图人工检查不可重复；本步骤临时引入新的 DOM 测试栈与变更规模不匹配。
