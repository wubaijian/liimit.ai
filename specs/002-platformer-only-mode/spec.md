# 功能规格：单一横版平台游戏模式

**功能标识**：`002-platformer-only-mode`

**创建日期**：2026-08-23

**状态**：草案

**输入**：用户描述：“在 liimit.ai 上直接修改，只保留 Phaser 2D、横版平台跳跃游戏、Web 浏览器试玩和固定游戏模板。第一步先把产品收敛成这一种模式。”

## 用户场景与测试（必填）

### 用户故事 1：不用选技术路线就能开始做游戏（优先级：P1）

新用户从首页发起新项目时，不再面对游戏类型、游戏引擎或运行目标选择。产品明确告诉用户将要创建的是一个可在浏览器试玩的 2D 横版平台跳跃游戏，用户只需提供项目所必需的信息即可继续。

**优先级原因**：这是本阶段最核心的产品收敛。只有把选择路径统一，后续固定模板、可视化编辑器和 AI 试玩才能建立在同一种项目上。

**独立测试**：从每一个可见的“新建项目”入口开始操作，确认用户在进入制作流程前看不到其它游戏类型、引擎或试玩目标选项，并且创建结果始终是同一种产品模式。

**验收场景**：

1. **假如**用户位于首页，**当**用户开始新项目，**那么**界面明确说明项目固定为 Phaser 3 · 2D 横版平台跳跃游戏，并使用应用内 Web 浏览器试玩。
2. **假如**用户正在填写新项目所需信息，**当**用户继续创建，**那么**系统不会要求用户选择其它游戏类型、引擎或运行目标。
3. **假如**应用中存在多个可见的新建入口，**当**用户分别使用这些入口，**那么**它们都会进入同一个固定模式，不会产生不同类型的项目。

---

### 用户故事 2：始终获得一致的浏览器试玩预期（优先级：P1）

用户在创建和查看项目时只会看到应用内隔离的 Web 浏览器试玩区（不是打开系统浏览器）这一种试玩目标，不会被 Godot、Unity、Blender 或其它外部游戏引擎的入口和说明分散注意力。

**优先级原因**：单一试玩目标能让用户清楚知道最终交付物是什么，也能显著缩小后续生成、验证和支持范围。

**独立测试**：完成一次新建项目流程并检查相关页面、操作和提示，确认只展示浏览器试玩能力；若试玩暂不可用，则显示清楚且可恢复的原因，而不是引导到其它引擎。

**验收场景**：

1. **假如**用户创建了新项目，**当**用户查看可用的试玩方式，**那么**只出现 Web 浏览器试玩。
2. **假如**浏览器试玩尚未准备好，**当**用户尝试试玩，**那么**系统说明当前缺少什么或需要等待什么，并保留用户项目，不切换到其它运行目标。
3. **假如**用户浏览本阶段保留的主要制作页面，**当**页面提到项目能力，**那么**能力说明与“Phaser 3 · 2D 横版平台跳跃游戏 + 应用内 Web 浏览器试玩”一致。

---

### 用户故事 3：产品收敛时不丢失已有项目和设置（优先级：P2）

升级前已经使用 liimit.ai 的用户不会因为新产品模式而丢失项目记录、项目文件或已有设置。旧项目不再作为新项目类型供用户选择，但仍按原有能力被识别和打开；暂时隐藏的设置也不会被自动删除。

**优先级原因**：产品方向可以收敛，但不能以破坏用户数据为代价；保留兼容性也让这一阶段能够安全回退。

**独立测试**：准备包含旧项目记录和已有设置的应用数据，升级后打开并关闭应用，确认记录、文件与设置没有被改写或删除，同时新建流程仍只有固定模式。

**验收场景**：

1. **假如**用户已有其它类型的项目记录，**当**用户升级并打开应用，**那么**这些记录与磁盘文件保持不变，且不会变成可复制的新建类型选项。
2. **假如**用户已有外部工具、插件或服务设置，**当**相关入口在本模式中不再显示，**那么**原设置仍被安全保留，不会在后台自动卸载或清空。
3. **假如**旧项目能够被现有版本打开，**当**用户从最近项目中重新打开它，**那么**系统继续采用兼容路径；若确实不再支持，则给出明确说明且不修改项目文件。

### 边界情况

- 用户通过不同首页按钮、空状态按钮或快捷入口新建项目时，所有入口必须落到同一个固定模式。
- 用户取消目录选择、目录不可写或创建中途失败时，不得留下一个被标记为成功的项目记录，也不得损坏已有目录。
- 旧版本保存的项目缺少类型信息、包含未知类型信息或指向已移动目录时，系统应保持数据不变并给出可理解的状态。
- 用户已有正在运行或可恢复的旧会话时，升级不能悄悄把它转换为新模式。
- 暂时隐藏的外部引擎、插件或依赖设置仍存在于本地数据中时，应用不得把“隐藏”当作“卸载”或“删除”。
- 通过历史链接或过期界面状态尝试创建非目标模式时，系统不得生成一个新的非目标项目；应回到固定模式或明确拒绝。

## 需求（必填）

### 功能需求

- **FR-001**：所有面向用户的新建项目入口必须采用唯一产品模式：Phaser 3 · 2D 横版平台跳跃游戏，并以应用内 Web 浏览器作为试玩目标。
- **FR-002**：用户在新建流程中不得选择其它游戏类型、游戏引擎、维度或运行目标。
- **FR-003**：系统必须在用户确认创建前清楚展示固定模式的游戏类型、引擎和试玩目标，不得把固定规则隐藏成意外行为。
- **FR-004**：来自首页、空状态和其它仍保留入口的新建请求必须得到一致结果。
- **FR-005**：新项目相关页面只能把现有 sandbox iframe 中的应用内 Web 浏览器试玩作为用户可操作的试玩方式，不得暗示会打开系统 Chrome、Safari 或其它外部浏览器。
- **FR-006**：新项目的主要创建与试玩路径不得展示外部游戏引擎选择、外部游戏工具启动或与目标模式无关的能力承诺。
- **FR-007**：任何过期入口或旧界面状态提交的非目标新建请求都必须被归一到固定模式或被明确拒绝，不得静默持久化为另一种新项目。
- **FR-008**：产品收敛不得自动删除、卸载、覆盖或迁移已有项目文件、项目记录、凭据、插件配置和外部工具设置。
- **FR-009**：旧项目不得重新出现在新建类型列表中；在现有兼容能力允许时仍可重新打开，不能打开时必须显示原因且不得修改项目文件。
- **FR-010**：取消、目录不可写或创建失败时，系统必须给出可执行的错误说明，并且不得生成误导性的成功记录。
- **FR-011**：本阶段所有面向用户的产品说明必须与实际保留能力一致，不得宣称已经具备可视化拖拽编辑或 AI 自动试玩。
- **FR-012**：本阶段的收敛必须可通过配置和界面行为完成验证，不以删除底层兼容代码或用户数据作为完成条件。
- **FR-013**：固定模式新项目暂时不得加载用户 Skills 或向 Agent Runtime 注入已保存的 MCP Server；相关配置和凭据必须保留，缺少固定标记的旧项目继续采用原有扩展行为。
- **FR-014**：设置中必须保留 Node.js/npm 构建运行环境的检测和恢复入口，只隐藏 Unity、Godot、Blender 等外部游戏引擎能力及与固定模式无关的工具入口。

### 关键实体

- **固定产品模式**：新项目唯一可采用的产品定义，包含“Phaser 3 · 2D”“横版平台跳跃游戏”“应用内 Web 浏览器试玩”三项不可由用户更改的属性。
- **项目记录**：应用用于重新打开本地项目的记录，至少关联显示名称、项目位置、当前状态以及是否属于固定产品模式。
- **旧项目**：在本功能启用前已存在或不符合固定产品模式的项目；它可以走兼容打开路径，但不能成为新建选项。
- **保留设置**：因产品收敛而暂时不展示、但仍需原样保存的插件、外部工具、凭据和服务配置。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：对所有可见新建入口进行验收时，100% 的创建结果都属于固定产品模式，且不存在其它游戏类型、引擎或运行目标选项。
- **SC-002**：首次用户在提供必要的项目名称和位置后，无需额外技术选择即可在 60 秒内进入项目制作界面；不计算用户挑选目录和外部服务响应时间，并以一次人工秒表验收记录作为证据。
- **SC-003**：对首页、新建流程、项目页和试玩相关页面进行文案与操作审查时，与其它游戏类型、外部引擎或非浏览器目标相关的可操作入口数量为 0。
- **SC-004**：使用包含旧项目和已有设置的测试数据完成一次升级、启动和退出后，项目记录、项目文件、Provider、凭据、插件和外部工具配置在语义上完整保留，不丢失项目或设置；允许现有 Runtime 对运行状态做既有的安全归一化。
- **SC-005**：无效或不可写目录、取消操作、过期入口和旧项目路径不存在四类异常场景均能得到明确且可执行的结果，且不会产生新的错误项目记录或改写用户项目。
- **SC-006**：不了解游戏引擎的测试用户仅根据界面文字，即可正确说出产品会制作“浏览器可玩的 2D 横版平台跳跃游戏”。

## 假设

- 本功能是第一阶段的第 1.2 步，只负责建立单一产品模式和收敛用户入口。
- 固定游戏模板的具体目录结构、场景数据协议和示例关卡属于后续第 1.3 步，本功能只明确它将是唯一模板。
- Agent 提示词的完整重写和新建后的自动制作流程属于后续第 1.4 步；本功能只增加使固定模式真实生效所必需、不可协商的产品边界约束，不承诺在本步骤提升生成质量。
- 插件中心、依赖管理和高级设置的进一步删除或重组属于后续第 1.5 步；本功能允许先从核心用户路径隐藏无关入口并保留底层兼容数据，同时必须保留 Node.js/npm 构建运行环境的检测与恢复入口。
- 可视化拖拽编辑器和 AI 自动试玩报告均不在本功能范围内，界面也不得提前宣称已经提供这些能力。
- 用户选择的项目目录继续作为本地项目的真实来源，应用不会接管或移动这些目录。
