# 实施计划：第一个真实可玩的横版游戏闭环

## 技术方案

1. 先把 `platformer-only` 已验证改动提交为独立 Git 基线，避免 M1 与上一阶段混合。
2. 为固定模板生成并携带锁文件；在受控的脚手架流程中校验模板包契约，再使用无 shell 的固定 npm 命令准备依赖。
3. 将依赖准备结果写成可验证状态，使相同锁定依赖可以跳过，锁文件变化时重新执行。
4. 为 `ProjectManager` 暴露无副作用的可试玩构建探测；AgentRunner 收到成功结果后先调用探测，再决定 `completed` 或可恢复状态。
5. 增加确定性最小关卡样板，验证固定脚手架、依赖、build、`dist/index.html` 和本地预览，不调用任何模型服务。

## 产品状态规则

| 条件                         | 项目状态    | 用户文案                      |
| ---------------------------- | ----------- | ----------------------------- |
| Runtime 失败                 | `failed`    | 展示 Runtime 根因             |
| Runtime 成功但没有可试玩构建 | `waiting`   | 生成尚未完成，可继续修复      |
| Runtime 成功且构建探测通过   | `completed` | 游戏生成完成，可载入 Web 试玩 |

## 风险与控制

- **供应链脚本风险**：只对固定模板及锁文件执行，拒绝已有未知清单；依赖版本由仓库评审。
- **安装耗时和网络失败**：设置超时、限制输出，返回重试说明；重复项目使用满足性检查跳过。
- **Runtime 成功误报**：完成状态集中经过同一探测函数，不依赖模型自述。
- **烟测把模型问题混入基础设施**：样板完全确定性，不使用 Provider。
- **真实模型仍未验证**：在报告中单独保留为需要 API、额度和明确授权的人工验收项。
