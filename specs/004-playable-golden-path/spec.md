# 功能规格：第一个真实可玩的横版游戏闭环

**功能编号**：004
**状态**：完成
**创建日期**：2026-08-23

## 用户目标

普通用户从空目录创建固定横版项目后，不需要打开终端或理解 npm。liimit.ai 必须自行准备受控依赖，并且只有在 Web 构建产物真实存在、能够由应用内预览服务读取时，才把项目显示为“生成完成”。

## 用户故事与验收

### US1：新项目自动准备依赖（P1）

对于“新项目立即获得可玩模板”功能上线后创建的新项目，项目记录安全保存后，应用会自动复制固定脚手架、准备构建依赖并验证游戏能否试玩；整个过程不要求用户先启动 Agent。依赖准备使用模板锁定的清单和受控进程，不允许模型临时选择包或版本。

没有 `starterPreparation` 字段的历史项目继续采用原有行为：应用不会在后台自动复制模板或安装依赖，也不会擅自改写历史项目。用户以后主动启动 Agent 时，原有的固定准备步骤仍作为幂等保护继续存在。

**验收场景**：从一个不含 `node_modules` 的新目录开始，脚手架复制后能够完成依赖准备；成功后可以执行模板构建。失败时返回具体中文原因，项目和用户配置不丢失。

### US2：只有可试玩构建才算完成（P1）

用户看到“游戏生成完成”时，项目必须至少存在安全、可读取的 `dist/index.html`。若 Agent 正常返回但没有构建产物，项目保持可继续修复的状态，并告诉用户缺少什么。

**验收场景**：相同的 Runtime 成功消息下，有有效构建产物的项目进入 `completed/complete`；缺少或不安全产物的项目进入可恢复状态，且不得发送误导性的“游戏生成完成”。

### US3：不调用付费模型也能验证基础闭环（P1）

开发者可以用确定性的横版样板验证“脚手架 → 依赖 → 构建 → 本地预览”基础设施，不把模型质量、素材 API 或额度问题混入基础设施测试。

**验收场景**：临时项目从固定模板开始，加入最小样板关卡，构建出 `dist/index.html`，再由与 Desktop 相同的安全预览规则提供并读取；测试结束后清理临时目录。

## 功能要求

- **FR-001**：模板必须包含可重复的依赖锁定信息；包名和版本不得来自用户 Prompt 或模型输出。
- **FR-002**：依赖准备必须使用参数数组启动受控进程，禁止拼接 shell 字符串。
- **FR-003**：依赖准备必须具有超时、退出码检查和长度受限的错误摘要。
- **FR-004**：已经满足锁定依赖的项目应跳过重复安装；锁定信息变化时必须重新准备。
- **FR-005**：不得对任意已有 `package.json` 静默执行安装；仅允许固定脚手架契约通过校验后执行。
- **FR-006**：依赖失败不得把项目标记为完成，也不得删除项目文件或用户设置。
- **FR-007**：Runtime 成功结果必须经过可试玩构建探测后才能映射为 `completed`。
- **FR-008**：探测失败必须产生可执行中文说明，并保留 Session 供用户继续修复。
- **FR-009**：Desktop 预览继续只服务项目内 `dist`，拒绝符号链接和越界路径。
- **FR-010**：确定性闭环不得调用主模型、图片、视频或音频服务。

## 成功标准

- **SC-001**：依赖准备聚焦测试覆盖首次成功、重复跳过、锁定变化、超时、非零退出和不可信清单拒绝。
- **SC-002**：完成门槛测试覆盖有效构建、缺失构建和不安全构建，且错误路径不会出现完成事件。
- **SC-003**：确定性样板可以在临时目录完成 build，并通过本地预览健康检查。
- **SC-004**：Desktop/Core 类型检查、全量测试、构建、Lint、打包 Runtime smoke 与 `git diff --check` 通过。

## 明确不做

- 本阶段不实现可视化拖拽编辑器。
- 本阶段不实现 AI 自动试玩或玩法质量判断。
- 本阶段不保证所有第三方模型或素材 Provider 的成功率。
- 未获得用户明确许可时，不调用付费模型生成黄金样板。
