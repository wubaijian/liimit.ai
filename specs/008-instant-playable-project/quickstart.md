# 验收指南：新项目立即获得可玩模板

本文件用于复核已经完成的实现；2026-08-26 的最终结果记录在 `implementation-evidence.md`。

## 前置条件

- Node.js 20+ 和 npm 可用。
- 不配置任何模型 API Key。
- 准备一个新的、可写的临时父目录。
- 允许首次从固定 npm registry 下载模板锁定的依赖。

## 自动检查

在仓库根目录运行：

```bash
npm run typecheck --workspace=@gameagent/desktop
npm test --workspace=@gameagent/desktop
npm run build --workspace=@gameagent/desktop
npm run smoke:playable --workspace=@gameagent/desktop
```

预期：全部退出码为 0；测试包含旧状态兼容、准备去重、失败恢复、IPC 门禁和零模型调用断言。

## 场景 A：不配置 AI 也能创建并试玩

1. 启动桌面开发版。
2. 保持所有模型密钥为空。
3. 新建项目并选择空的可写父目录。
4. 提交后确认项目立即出现，页面先显示真实准备阶段。
5. 等待状态变为完成。
6. 打开关卡页，确认展示来自项目 `src/level.json`。
7. 打开 Web 试玩，确认角色能移动和跳跃。
8. 不启动 Agent，启动自动试玩并确认它能读取同一个游戏和关卡。

通过标准：项目磁盘上存在真实 `src/level.json` 和 `dist/`；人工试玩和自动试玩入口都可加载同一内容；生成式 AI 调用数为 0。

## 场景 B：失败后保留并重试

1. 在依赖阶段模拟断网或受控安装失败。
2. 确认项目名称、目录和游戏想法仍在。
3. 记录失败前已经安全写入的模板文件内容或哈希，确认失败后仍然保留。
4. 确认关卡和试玩不显示虚假成功内容。
5. 恢复网络后点击一次“重试准备”。
6. 快速重复点击，确认只执行一份准备任务。

通过标准：失败原因可理解；不要求重填表单；成功后同一项目进入可编辑、可试玩状态。

## 场景 C：应用中途退出

1. 在依赖或构建阶段关闭应用。
2. 重新打开应用。
3. 选择原项目。

通过标准：关闭应用时受控准备任务和子进程停止；重新打开后项目显示“上次准备被中断”并可重试，不永久转圈，也不自动执行新的依赖命令。

## 场景 D：历史项目不被覆盖

1. 用包含用户修改文件、但没有 `starterPreparation` 字段的旧状态启动应用。
2. 打开旧项目并记录关键文件哈希。
3. 不点击任何历史修复操作，重启应用。

通过标准：旧项目不自动复制模板、不自动安装、不自动构建；关键文件哈希不变；旧项目原有界面行为保持。

## 场景 E：成功证据不是文字状态

分别模拟：缺少 `src/level.json`、构建失败、`dist/index.html` 无效、关键游戏资源无法加载。

通过标准：每一种情况都进入 failed，不得出现 ready；修复后可由同一重试入口再次验证。
