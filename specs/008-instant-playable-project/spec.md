# 功能规格：新项目立即获得可玩模板

**功能分支**：`codex/platformer-only-baseline`

**创建日期**：2026-08-24

**状态**：已完成并验收

**完成日期**：2026-08-26

**用户描述**：新建固定横版项目后，不依赖付费 AI Agent，也能直接获得可以编辑和 Web 试玩的基础游戏。

## 用户场景与测试

### 用户故事 1：新建后直接进入可玩项目（P1）

普通用户填写项目名称、保存位置和游戏想法后，liimit.ai 自动准备固定横版基础游戏。用户不需要填写模型密钥、不需要启动 Agent，也不需要打开终端，就能进入真实关卡编辑器并在应用内 Web 浏览器试玩。

**优先级原因**：这是从“演示能力”变成“普通用户可以使用”的必要入口。没有这一步，新用户会在创建项目后停留在一个不能试玩的空目录。

**独立测试**：从一个新的可写目录创建项目，不配置任何模型服务；准备结束后，确认关卡编辑器读取到真实关卡文件，并能载入可运行的 Web 游戏。

**验收场景**：

1. **假如**用户没有配置任何模型服务，**当**用户成功提交新建项目表单，**那么**系统自动准备固定横版基础游戏，整个过程不调用任何生成式 AI 服务。
2. **假如**基础游戏已经准备完成，**当**用户打开关卡编辑器和 Web 试玩，**那么**两处展示的是同一份真实关卡，并且游戏可以在应用内运行。
3. **假如**项目仍在准备，**当**用户查看关卡或 Web 试玩区域，**那么**系统显示真实准备状态，不展示尚未写入磁盘的虚假默认关卡。

---

### 用户故事 2：看懂准备进度和失败原因（P1）

用户能够知道系统正在复制模板、准备运行环境还是构建游戏。准备失败时，项目和用户填写的游戏想法仍然保留，并提供清楚的失败原因和重试入口。

**优先级原因**：首次准备可能受到网络、磁盘空间或本机运行环境影响。没有可见状态和恢复入口，用户会误以为产品卡死或项目丢失。

**独立测试**：分别模拟成功、断网、空间不足和应用中途关闭；确认每种情况下都能看到明确状态，失败项目可在不重新填写表单的情况下重试。

**验收场景**：

1. **假如**基础游戏正在准备，**当**用户查看项目，**那么**系统明确显示当前仍在处理中，并阻止把项目误报为“可试玩”。
2. **假如**准备失败，**当**用户返回项目，**那么**项目名称、保存位置和游戏想法仍然存在，并显示可理解的中文原因与重试入口。
3. **假如**用户重试且准备成功，**当**流程结束，**那么**项目进入可编辑、可试玩状态，不需要重新创建项目。
4. **假如**应用在准备期间退出，**当**用户再次打开应用，**那么**项目不会永久显示为处理中，而是提供安全重试方式。

---

### 用户故事 3：保留 AI 创作作为可选后续步骤（P2）

用户先获得一个确定可玩的基础游戏，之后仍可选择启动 Agent，根据自己的想法继续修改游戏。基础模板准备和 AI 创作是两个清楚分开的步骤。

**优先级原因**：产品仍然需要 AI 创作能力，但不应把付费模型变成体验基础编辑、试玩和自动测试的前置条件。

**独立测试**：不启动 Agent 时确认基础游戏完整可用；随后配置模型并启动 Agent，确认系统继续在同一项目上工作，而不是重新创建或覆盖用户已经完成的关卡编辑。

**验收场景**：

1. **假如**基础模板已经可玩，**当**用户没有启动 Agent，**那么**关卡编辑、人工试玩和自动试玩仍可使用。
2. **假如**用户已经手动编辑关卡，**当**用户之后选择启动 Agent，**那么**系统保留现有项目，并明确提示 Agent 可能继续修改项目文件。

### 边界情况

- 项目名称或保存位置无效时，不创建半成品项目。
- 目标目录已经包含其他文件时，不静默覆盖用户文件。
- 网络不可用、依赖来源不可达、磁盘空间不足或权限不足时，保留项目记录并展示对应原因。
- 同一个项目被连续点击多次“重试”时，只运行一次准备流程，避免互相覆盖。
- 用户切换到其他项目时，当前项目的准备结果不会写入错误项目。
- 应用在准备过程中退出或异常终止时，下次启动不会把旧的处理中状态当作成功。
- 已经存在的历史项目不会在用户不知情时被自动覆盖或重建。

## 需求

### 功能需求

- **FR-001**：系统必须在新建固定横版项目后自动准备一份真实、可运行的基础游戏。
- **FR-002**：基础游戏准备不得要求模型密钥，也不得调用文字、图片、音频或视频生成服务。
- **FR-003**：只有真实关卡和可试玩版本都准备完成后，系统才可以把项目显示为可编辑、可试玩。
- **FR-004**：准备期间，系统必须展示明确的处理中状态，并且不得展示尚未保存的虚假默认关卡。
- **FR-005**：准备失败时，系统必须保留项目名称、保存位置、游戏想法和已经安全写入的文件。
- **FR-006**：准备失败必须显示可执行的中文说明，并提供由用户主动触发的重试入口。
- **FR-007**：重复重试必须按顺序执行或合并，不能让多个准备流程同时修改同一个项目。
- **FR-008**：应用重启后必须识别未完成的准备流程，并允许用户安全重试，不能永久停留在处理中。
- **FR-009**：基础模板成功后，关卡编辑器、Web 试玩、人工试玩和自动试玩必须读取同一项目中的真实内容。
- **FR-010**：用户之后启动 Agent 时，系统必须继续使用同一项目，并保留用户已经完成的编辑。
- **FR-011**：系统不得自动覆盖已有历史项目；本功能不提供历史项目的自动准备或修复入口。
- **FR-012**：任何成功提示都必须以实际可读取、可运行的游戏为依据，不能只依赖流程状态或文字结果。

### 关键实体

- **项目**：用户创建的固定横版游戏，包含名称、保存位置、游戏想法和当前可用状态。
- **基础游戏准备状态**：表示项目尚未准备、正在准备、已经可玩或准备失败，并包含用户可理解的失败原因。
- **可玩基础游戏**：已经写入真实关卡并能够在应用内运行的固定横版游戏，不依赖生成式 AI 服务。

## 成功标准

### 可衡量结果

- **SC-001**：在没有配置模型服务的测试环境中，新项目可以从提交表单走到关卡可编辑、Web 可试玩，全程生成式 AI 调用次数为 0。
- **SC-002**：成功完成的每个新项目都同时具有真实关卡和可运行游戏；不存在“显示成功但无法试玩”的验收样本。
- **SC-003**：准备失败的所有验收样本都保留项目资料，并能由用户通过一个明确的重试操作继续，不要求重新填写新建表单。
- **SC-004**：应用中途退出的验收样本在重新打开后都能恢复为可理解、可重试的状态，不会无限显示处理中。
- **SC-005**：用户从新建项目到首次试玩不需要使用终端，也不需要理解依赖安装、构建或目录结构。
- **SC-006**：关卡编辑器在真实关卡尚未存在时，虚假默认关卡展示次数为 0。

## 假设

- 用户创建的是产品已经固定支持的横版平台跳跃项目，不提供其他游戏类型选择。
- 首次准备可能需要下载固定运行环境，因此完成时间受网络状况影响；界面必须持续提供真实状态。
- 基础模板只提供一个可玩的起点，不承诺根据用户输入自动生成独特玩法、素材或关卡。
- 历史项目的自动迁移不包含在本功能内；本功能只保证新建项目，并为历史项目保留后续主动修复空间。

## 明确不做

- 不自动启动 Agent，不自动发送用户游戏想法给模型服务。
- 不在本阶段生成独特图片、音频、剧情或多种游戏模板。
- 不自动覆盖或重建历史项目。
- 不增加其他游戏类型、其他引擎或 3D 模式。
- 不在本阶段实现项目发布、云同步或多人协作。
