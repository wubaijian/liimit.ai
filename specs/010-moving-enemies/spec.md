# Feature Specification: 掉落死亡与移动敌人

**Feature Branch**: `main`

**Created**: 2026-08-27

**Status**: Draft

**Input**: User description: "角色从台阶之间掉到关卡底下时应当死亡；编辑器正式支持史莱姆和蜜蜂，并让它们可以移动。"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 掉出关卡立即死亡 (Priority: P1)

玩家从没有地面的台阶间隙掉下去时，游戏应明确判定本次尝试失败，而不是让角色继续掉落或停留在画面外。

**Why this priority**: 掉落是横版平台游戏最基本的失败规则；缺失该规则会让关卡无法正常进行。

**Independent Test**: 在任意含台阶间隙的关卡中主动走下平台，确认角色掉出可玩区域后计为一次死亡，并从当前关可用的复活位置重新开始。

**Acceptance Scenarios**:

1. **Given** 玩家位于平台边缘且下方没有可站立地面，**When** 玩家掉出关卡底部，**Then** 游戏记录一次“坠落死亡”，扣除一次生命并从当前关复活。
2. **Given** 玩家已经到达本关检查点，**When** 玩家随后掉出关卡底部，**Then** 玩家从该检查点复活。
3. **Given** 玩家在普通平台上跳跃且仍位于可玩区域，**When** 玩家落回平台，**Then** 不会被错误判定为死亡。

---

### User Story 2 - 正式识别和编辑敌人 (Priority: P2)

关卡设计者能在编辑器里清楚区分史莱姆、蜜蜂和尖刺，并能选择、拖动、复制或删除这些敌人。

**Why this priority**: 编辑器显示的内容必须和最终试玩一致，否则设计者无法理解自己正在编辑什么。

**Independent Test**: 打开包含史莱姆和蜜蜂的关卡，确认二者有独立名称和外观；移动一个敌人并保存后，重新打开关卡仍位于新位置。

**Acceptance Scenarios**:

1. **Given** 关卡包含史莱姆和蜜蜂，**When** 设计者打开可视化编辑器，**Then** 两种敌人分别显示正确名称和可辨认图案，不再显示为尖刺。
2. **Given** 设计者选中一个敌人，**When** 拖动、复制或删除并保存，**Then** 编辑器和网页试玩都反映同一结果。
3. **Given** 一个旧关卡只使用已有物体类别，**When** 平台读取该关卡，**Then** 旧关卡仍可正常编辑和试玩。

---

### User Story 3 - 敌人按范围巡逻 (Priority: P3)

玩家试玩时，史莱姆在地面上左右巡逻，蜜蜂在空中往返飞行；玩家需要观察并躲避或踩踏敌人。

**Why this priority**: 移动敌人能让固定关卡产生节奏和挑战，但它依赖前两项基础规则正确。

**Independent Test**: 从任意含两类敌人的关卡开始试玩，观察至少一个完整往返过程，并验证正面碰撞和从上方踩踏的结果。

**Acceptance Scenarios**:

1. **Given** 史莱姆位于可站立的平台上，**When** 玩家不与它交互，**Then** 它在自己的巡逻范围内来回移动且不会走出关卡。
2. **Given** 蜜蜂位于空中，**When** 玩家不与它交互，**Then** 它在自己的巡逻范围内往返飞行且不会飞出关卡。
3. **Given** 玩家从上方向下踩到敌人，**When** 碰撞发生，**Then** 敌人被消灭且玩家向上弹起。
4. **Given** 玩家从正面或侧面碰到敌人，**When** 碰撞发生，**Then** 玩家死亡并按当前关规则复活。

### Edge Cases

- 敌人的巡逻范围碰到关卡边界时，敌人必须在边界内转向。
- 敌人附近没有足够大的平台时，史莱姆仍须被限制在配置范围内，不得无限坠落。
- 玩家与敌人高速接触时，同一次碰撞只能产生一次踩踏或一次死亡结果。
- 旧项目中用于临时代表敌人的特定尖刺编号需要兼容转换，同时普通尖刺保持不变。
- 角色的生命用尽时，沿用现有的关卡失败和重新开始流程。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 系统必须在玩家完整离开关卡底部时判定坠落死亡，并记录可识别的死亡原因。
- **FR-002**: 坠落死亡必须使用现有的生命、死亡次数、检查点和当前关重开规则。
- **FR-003**: 系统必须把“史莱姆”和“蜜蜂”作为不同于“尖刺”的正式关卡物体类别保存、读取和展示。
- **FR-004**: 编辑器必须为史莱姆和蜜蜂提供独立的中文名称与易区分图案。
- **FR-005**: 设计者必须能选择、拖动、复制和删除史莱姆与蜜蜂，并保存结果。
- **FR-006**: 史莱姆必须在可配置的水平范围内往返巡逻。
- **FR-007**: 蜜蜂必须在可配置的飞行范围内往返巡逻。
- **FR-008**: 敌人移动的方向、距离和速度必须随关卡数据保存，未提供时使用安全且可试玩的默认值。
- **FR-009**: 玩家从上方踩中史莱姆或蜜蜂时必须消灭该敌人并弹起；从其他方向接触时玩家必须死亡。
- **FR-010**: 已有普通尖刺、旧关卡和当前“星光森林”五关必须继续可读取；旧的临时敌人标记必须转换为正式敌人类别。
- **FR-011**: 编辑器画面和网页试玩必须使用同一份敌人位置与移动设置。

### Key Entities _(include if feature involves data)_

- **敌人物体**: 关卡中的史莱姆或蜜蜂，包含编号、类别、位置、大小以及巡逻方向、距离和速度。
- **坠落死亡**: 玩家越过关卡底部形成的一次失败记录，参与生命扣除、死亡计数、复活和试玩观察。
- **巡逻范围**: 敌人围绕初始位置允许往返移动的区间，必须保持在关卡范围内。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 在五个现有关卡中进行的每次无地面坠落，都能在角色离开画面后 1 秒内被判定为死亡并启动复活。
- **SC-002**: 设计者无需进入试玩，仅凭编辑器图案和名称即可在 5 秒内区分尖刺、史莱姆和蜜蜂。
- **SC-003**: 史莱姆和蜜蜂连续完成 10 次往返巡逻时，均不会离开关卡范围或静止失效。
- **SC-004**: 对两类敌人分别进行移动、复制和删除后，重新打开项目的保存结果准确率为 100%。
- **SC-005**: 当前五关以及至少一个不包含新敌人的旧项目全部可以继续打开、编辑和试玩。

## Assumptions

- 第一版仅提供史莱姆和蜜蜂两种敌人，不在本次增加攻击、生命值、掉落奖励或更多敌人种类。
- 史莱姆默认水平巡逻；蜜蜂默认水平飞行。两者第一版均不主动追踪玩家。
- 新增敌人默认采用项目现有的矢量画风，不要求下载新的外部美术素材。
- 掉落死亡不要求在每个空隙下额外摆放尖刺或陷阱。
