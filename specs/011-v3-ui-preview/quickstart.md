# Quickstart: 多游戏类型界面预览验收

## 自动检查

1. 运行桌面端聚焦测试，确认新建分流、预览文案和无特权调用契约。
2. 运行桌面端两个 TypeScript 配置检查。
3. 运行完整桌面端测试，确认现有 Phaser 创建、关卡编辑、Web 试玩和 Agent 门禁测试不回归。
4. 运行桌面端生产构建。

## 人工界面检查

1. 启动 liimit.ai，打开“新建游戏”。
2. 切换“横版平台跳跃”和“俯视角迷宫”，确认引擎、可用状态、创建方式和主按钮文案清晰变化。
3. 选择横版类型，确认仍能按现有流程创建真实 Phaser 项目。
4. 重新打开新建窗口，选择迷宫类型并进入预览；确认项目列表没有新增记录，磁盘没有新增项目目录。
5. 在迷宫工作台中切换关卡、点击物体，确认画布选择与属性区域同步。
6. 依次打开 AI 助手、Web 试玩、自动验证和导出，确认都显示界面状态与未接入提示。
7. 点击保存、确认修改、开始试玩或导出等动作，确认只出现“界面预览，不会执行真实操作”的反馈。
8. 关闭迷宫预览，确认原来选中的 Phaser 项目、项目文件和 Agent 状态均未变化。
9. 缩小窗口，确认返回入口、主要操作和各面板可通过换行或滚动访问。

## 通过标准

- 两种产品方向一眼可区分。
- 所有 Godot 相关页面均不会被误认为已经交付。
- 迷宫预览产生的真实项目、文件、Agent 调用、构建和外部程序启动数量均为 0。
- 现有 Phaser 功能自动检查全部通过。
