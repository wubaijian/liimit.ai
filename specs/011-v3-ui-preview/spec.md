# Feature Specification: 多游戏类型界面预览

**Feature Branch**: `main`

**Created**: 2026-09-01

**Status**: Draft

**Input**: User description: "按照第三版需求文档修改游戏平台：保留现有横版跳跃能力，增加俯视角迷宫与 Godot 相关界面，但本次只增加 UI，不接入实际效果。"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 新建时看懂两种游戏方向 (Priority: P1)

公司内部的游戏制作人员新建项目时，可以先选择“横版平台跳跃”或“俯视角迷宫”，并立即看见系统为该类型匹配的游戏引擎、当前可用程度和创建方式，避免把规划中的能力当成已经完成的能力。

**Why this priority**: 这是用户进入第三版产品的第一个关键入口，也是区分现有真实功能和新增界面预览的最重要保护。

**Independent Test**: 打开新建项目窗口，分别选择两种游戏类型，确认引擎、状态、说明和主按钮随选择清楚变化；不需要真正创建项目即可完成验证。

**Acceptance Scenarios**:

1. **Given** 用户打开新建项目窗口，**When** 选择横版平台跳跃，**Then** 页面显示 Phaser 3、Web 试玩和“当前可用”，并保留原有真实创建入口。
2. **Given** 用户打开新建项目窗口，**When** 选择俯视角迷宫，**Then** 页面显示 Godot 和“界面预览，尚未接入”，主按钮只进入预览工作台。
3. **Given** 用户选择任意游戏类型，**When** 查看创建方式，**Then** 可以看见固定模板与 AI 生成两个入口，以及各自是否已经可用的说明。
4. **Given** 用户尚未填写项目名称，**When** 尝试进入迷宫预览，**Then** 页面用示例名称继续展示，不会创建或写入真实项目。

---

### User Story 2 - 查看迷宫编辑器完整外观 (Priority: P2)

产品经理和内部测试人员可以进入一个俯视角迷宫工作台，查看关卡管理、物体工具、迷宫画布、属性区域和顶部操作区将来是什么样子，并能通过有限的本地界面交互理解页面结构。

**Why this priority**: 第三版首先需要验证信息架构和操作路径是否易懂，再决定是否投入真实 Godot 开发。

**Independent Test**: 从新建项目窗口进入迷宫界面预览，确认一个屏幕内能找到关卡、物体、画布、属性和主要操作按钮，并能切换关卡或选择物体查看界面反馈。

**Acceptance Scenarios**:

1. **Given** 用户进入迷宫界面预览，**When** 浏览工作台，**Then** 顶部显示保存、Web 试玩、自动验证、AI 助手和导出入口。
2. **Given** 用户查看左侧区域，**When** 浏览关卡与物体工具，**Then** 可以看见 1～8 关管理入口，以及出生点、墙壁、障碍、钥匙、门、敌人、出口和装饰物。
3. **Given** 用户点击不同关卡或画布物体，**When** 当前选择发生变化，**Then** 画布选中提示和右侧属性区域同步显示对应的界面信息，但不写入任何项目文件。
4. **Given** 用户查看预览工作台任意位置，**When** 判断功能是否可用，**Then** 始终能看见“界面预览/尚未接入”的明确提示。

---

### User Story 3 - 预览制作闭环的关键状态 (Priority: P3)

用户可以查看 AI 建议、指定关卡 Web 试玩、自动验证、保存和导出的计划界面，理解第三版未来会如何从编辑走到确认、修改、复测和交付。

**Why this priority**: 这些状态决定完整产品体验，但本轮只需要验证布局、文案和操作顺序，不应产生真实副作用。

**Independent Test**: 在迷宫预览中依次打开 AI 助手、Web 试玩、自动验证和导出界面，确认每个界面都有状态说明、下一步按钮及“不会真实执行”的保护提示。

**Acceptance Scenarios**:

1. **Given** 用户打开 AI 助手，**When** 查看状态区域，**Then** 页面可展示等待、分析、待确认、执行、验证、完成、失败和停止等状态名称，并说明确认后才修改。
2. **Given** 用户打开 Web 试玩，**When** 选择起始关卡，**Then** 页面展示关卡选择与浏览器试玩外观，但不会构建或运行 Godot 游戏。
3. **Given** 用户打开自动验证，**When** 查看结果，**Then** 页面展示起点、出口、路线、钥匙和门等检查项，以及“用户确认后修改”的后续入口。
4. **Given** 用户打开保存或导出，**When** 选择 Godot 工程或 Web 文件，**Then** 页面说明目标产物和未接入状态，不创建文件、不覆盖目录。

### Edge Cases

- 用户从迷宫预览返回后，原有项目列表、当前选中的 Phaser 项目和本地文件必须保持不变。
- 用户反复打开或关闭预览弹层时，不得启动 Agent、浏览器构建、文件保存或外部程序。
- 窗口较小时，主要区域必须仍可滚动或换行，不能因为预览内容较多而遮住返回入口。
- 没有配置 API 时，AI 预览仍可查看界面，但必须明确它只是流程说明，不是假装已经连接。
- 已有 Phaser 项目继续按原有方式打开、编辑、试玩和运行 AI，不出现 Godot 兼容假象。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 新建项目界面必须提供“横版平台跳跃”和“俯视角迷宫”两个清晰可区分的游戏类型入口。
- **FR-002**: 横版平台跳跃入口必须标记 Phaser 3、2D、Web 试玩和“当前可用”。
- **FR-003**: 俯视角迷宫入口必须标记 Godot、2D 和“界面预览，尚未接入”。
- **FR-004**: 新建界面必须展示固定模板与 AI 生成两种创建方式，并对未接入选项做明显说明。
- **FR-005**: 选择横版平台跳跃并提交时，必须继续调用现有真实创建流程，不改变现有项目数据或行为。
- **FR-006**: 选择俯视角迷宫并提交时，只能打开内存中的界面预览，不得创建项目记录、目录、文件或 Agent 任务。
- **FR-007**: 现有项目列表和项目顶部必须继续显示 Phaser 横版项目的真实类型与引擎标识。
- **FR-008**: 迷宫预览工作台必须包含顶部操作区、关卡区、物体工具区、中心画布和属性区。
- **FR-009**: 顶部操作区必须展示保存、Web 试玩、自动验证、AI 助手和导出入口。
- **FR-010**: 关卡区必须展示新建、复制、删除、改名和调整顺序的界面，并说明第一版最多 8 关。
- **FR-011**: 物体工具区必须展示玩家出生点、墙壁、障碍、钥匙、门、敌人、出口和装饰物。
- **FR-012**: 迷宫画布必须提供可辨认的示例关卡，并允许用户通过点击切换当前选中物体的界面状态。
- **FR-013**: 属性区必须随示例物体选择展示名称、类型、位置和与该类型相关的示例设置。
- **FR-014**: AI 助手界面必须展示可观察的任务状态、修改摘要和用户确认入口，不展示隐藏推理内容。
- **FR-015**: Web 试玩界面必须提供起始关卡选择和加载、试玩、死亡、通关、失败等状态说明。
- **FR-016**: 自动验证界面必须展示起点、出口、路线、钥匙/门和敌人等检查项及问题建议。
- **FR-017**: 导出界面必须展示 Godot 工程和 Web 文件两种计划产物，并明确本轮不会真实导出。
- **FR-018**: 所有会让用户以为发生真实保存、生成、试玩、验证、AI 修改或导出的按钮，都必须返回“界面预览，不会执行真实操作”的可见反馈。
- **FR-019**: 迷宫预览必须提供随时返回现有 liimit.ai 工作台的入口，并在返回时丢弃所有预览状态。
- **FR-020**: 本次不得新增或修改主进程、预加载桥、IPC、持久化结构、Godot 依赖、Agent 运行时或导出服务。

### Key Entities _(include if feature involves data)_

- **游戏类型选项**: 新建项目时展示的产品方向，包含名称、匹配引擎、可用状态和说明；本轮只有横版类型可创建真实项目。
- **迷宫预览项目**: 仅存在于当前界面会话中的示例名称、关卡选择、物体选择和弹层状态，关闭后全部丢弃。
- **预览操作状态**: AI、试玩、验证、保存和导出界面用于说明流程的状态，不对应真实任务或文件结果。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 新用户在 30 秒内能够说清两种游戏类型分别匹配哪个引擎，以及哪一种目前只提供界面预览。
- **SC-002**: 用户进入迷宫预览后，在 60 秒内能找到关卡、物体、画布、属性、试玩、AI、验证和导出八类界面入口。
- **SC-003**: 对所有迷宫预览操作进行一轮点击后，真实项目数量、项目文件和 Agent 运行状态变化均为 0。
- **SC-004**: 现有 Phaser 项目的创建、打开、关卡编辑、Web 试玩和 AI 入口相关自动测试通过率保持 100%。
- **SC-005**: 在桌面端支持的最小窗口布局下，迷宫预览仍能通过滚动访问返回按钮和五个顶部操作入口。
- **SC-006**: 由一名不了解实现细节的内部用户检查全部迷宫页面时，规划能力被误判为已交付能力的次数为 0。

## Assumptions

- 本轮目标是验证第三版的页面结构和文案，不验证 Godot 可行性、游戏玩法或生成质量。
- “点得动”仅指界面切换、选择、弹层和提示反馈，不包含保存、拖拽持久化、构建或运行游戏。
- 原有 Phaser 项目的数据结构保持唯一真实项目结构；不为预览增加兼容字段或迁移逻辑。
- 迷宫示例使用本地界面图形组成，不新增下载素材或外部网页。
- 下一轮是否接入真实 Godot 能力，需要在本轮界面评审完成后另行立项和确认。
