# Feature Specification: 正式化演示界面

**Feature Branch**: `main`

**Created**: 2026-09-01

**Status**: Draft

**Input**: User description: "去掉界面中反复出现的‘界面预览’、‘尚未接入’、‘当前只做 UI’等半成品文案，让普通用户打开后看到一个正常、完整、可用于展示效果的产品界面。"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 打开后像正式产品 (Priority: P1)

产品经理、公司领导或内部测试人员打开 liimit.ai 时，看到的是正常的游戏类型、引擎和创作入口，而不是开发说明、半成品警告和重复的预览提示。

**Why this priority**: 首屏和新建项目是展示中最先被看到的部分，直接决定产品是否像一个已经设计完整的工具。

**Independent Test**: 打开首页和新建项目窗口，不点击任何高风险操作，确认页面主文案只讲游戏创作能力，不再反复讲开发阶段。

**Acceptance Scenarios**:

1. **Given** 用户打开首页，**When** 查看游戏类型区域，**Then** 页面以正式产品语气展示横版平台跳跃和俯视角迷宫两种方向。
2. **Given** 用户打开新建窗口，**When** 切换两种游戏类型，**Then** 类型、引擎、创建方式和按钮都像正常产品选项，不显示“当前可用”与“界面预览”的开发对比。
3. **Given** 用户查看 Godot 迷宫入口，**When** 需要判断当前环境，**Then** 页面只使用一个简洁、不抢视觉焦点的“演示模式”标识。

---

### User Story 2 - 迷宫工作台像完整工具 (Priority: P2)

用户进入迷宫工作台后，可以自然地查看关卡、物体、画布、属性、AI、试玩、验证、保存和导出，界面不再用大面积警告和预览文案打断操作感。

**Why this priority**: 迷宫工作台是第三版最重要的展示画面，需要看起来统一、成熟和可操作。

**Independent Test**: 进入迷宫工作台，查看顶部、三栏编辑区和五个功能面板，确认没有重复的开发阶段文案。

**Acceptance Scenarios**:

1. **Given** 用户进入迷宫工作台，**When** 查看顶部和编辑区，**Then** 只看到产品名称、游戏类型、引擎、操作入口与编辑内容。
2. **Given** 用户打开 AI、试玩、验证、保存或导出面板，**When** 阅读标题与内容，**Then** 面板使用正常产品文案，不以“预览”、“计划状态”或“未接入”作为主信息。
3. **Given** 用户从迷宫工作台返回，**When** 重新查看现有项目，**Then** 原有 Phaser 项目数量、选中状态和文件保持不变。

---

### User Story 3 - 只在操作时告知演示边界 (Priority: P3)

用户可以先完整体验产品界面；只有当用户点击会让人以为已经保存、生成、修改、验证或导出的按钮时，系统才用一条简短消息说明当前是演示操作，不会写入真实数据。

**Why this priority**: 这在“展示效果”和“不误导测试人员”之间保留最小但必要的边界。

**Independent Test**: 在默认工作台中不触发操作，确认没有大段警告；再点击保存、AI 确认、试玩、验证和导出，确认每次都出现同一风格的简短演示提示。

**Acceptance Scenarios**:

1. **Given** 用户只是浏览页面，**When** 没有点击结果型按钮，**Then** 界面不显示大面积、重复或阻断式的未完成说明。
2. **Given** 用户点击结果型按钮，**When** 系统不执行真实操作，**Then** 页面显示“演示模式：本次操作不会写入真实项目”或同等简短文案。
3. **Given** 用户打开包含示例验证结果的面板，**When** 查看结果，**Then** 只使用小型“示例数据”标识，不用大段警告占据视觉主位。

### Edge Cases

- 在小窗口下，唯一的“演示模式”标识不得挤掉返回按钮或顶部功能入口。
- 用户连续点击多个演示操作时，提示应替换上一条消息，不能层层堆叠。
- 用户打开真实 Phaser 项目时，不得看到 Godot 演示标识或演示提示。
- 演示工作台不得因文案精简而新增文件、项目记录、Agent 任务或 Godot 进程。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 首页必须使用正式产品语气展示两种游戏类型，不得以开发完成度对比作为主内容。
- **FR-002**: 新建项目窗口必须去除“当前可用”、“界面预览”、“尚未接入”、“当前只做 UI”等重复的开发阶段文案。
- **FR-003**: 新建项目窗口必须保留游戏类型、引擎、创建方式、项目名称、位置和主题想法的完整信息。
- **FR-004**: Godot 迷宫路径必须只保留一个弱化的“演示模式”标识，且不得在首页、类型卡、顶部、说明条和底部同时重复。
- **FR-005**: 迷宫工作台必须移除顶部的大面积开发说明条与底部重复提示。
- **FR-006**: 迷宫工作台的主标题、区域标题、按钮和属性文案必须使用正常操作语气，不在按钮名称中附加“预览”。
- **FR-007**: AI、Web 试玩、自动验证、保存和导出面板必须移除开发阶段前缀、大面积未接入说明与“计划产物”类文案。
- **FR-008**: 包含示例验证结果或示例修改方案的面板必须用小型“示例数据”标识与真实结果区分。
- **FR-009**: 所有不会执行真实保存、生成、AI 修改、试玩、验证或导出的结果型按钮，点击后必须显示简短的演示模式提示。
- **FR-010**: 演示提示必须使用同一位置和同一视觉样式，新消息必须替换旧消息。
- **FR-011**: 文案和视觉调整不得调用 `window.gameAgent`、不得新增 IPC、文件写入、Godot 依赖、Agent 任务或持久化字段。
- **FR-012**: 原有 Phaser 项目的创建、打开、编辑、Web 试玩、AI 入口和项目标识必须保持不变。
- **FR-013**: 现有 liimit.ai 品牌、浅色视觉与响应式布局必须保持一致。

### Key Entities

- **演示模式标识**: 只在 Godot 迷宫工作台显示的一枚弱化状态标识，用来取代多处重复的开发说明。
- **演示操作提示**: 只在用户点击不会产生真实结果的按钮后显示的短消息，新消息会替换旧消息。
- **示例数据标识**: 附着在静态验证结果和 AI 修改方案上的小型说明，不作为主要视觉内容。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 首页、新建项目窗口和迷宫工作台默认状态中，以“界面预览”、“尚未接入”、“当前只做 UI”或“不会执行真实操作”为主内容的可见文案数量为 0。
- **SC-002**: Godot 迷宫工作台默认状态只显示 1 处“演示模式”标识。
- **SC-003**: 用户在 30 秒内能看懂首页的两种游戏方向，且不需要阅读任何开发状态说明。
- **SC-004**: 逐一点击所有 Godot 结果型操作后，每次都有 1 条简短演示提示，且实际项目、文件和 Agent 状态变化数为 0。
- **SC-005**: 原有 Phaser 类型契约、完整桌面测试和可玩流程检查通过率保持 100%。
- **SC-006**: 在窄窗口和宽窗口下，返回按钮、顶部操作、编辑区和演示提示都可正常查看。

## Assumptions

- 用户要求的“相当于已经做好”指视觉与操作流程像正式产品，不包含伪造文件、真实保存结果或 Agent 执行结果。
- 为满足产品事实一致性，默认页面只保留一枚轻量“演示模式”标识，其余边界信息只在产生结果的操作被点击时出现。
- 本次仅调整现有渲染层文案、标签和局部样式，不扩展真实 Godot 能力。
- 现有 Phaser 项目与用户自定义 Agent 提示词修改属于必须保留的工作区内容。
