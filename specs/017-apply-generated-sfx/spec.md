# Feature Specification: 将生成音效应用到当前游戏

**Feature Branch**: `main`

**Created**: 2026-09-02

**Status**: Implemented

**Input**: 在已具备音效 API 试听、六种内置音效和声音控制后，继续补齐“生成结果只能试听，不能用于游戏”的缺口。用户选择用途，试听满意后确认应用到当前项目。

## User Story - 把满意的 AI 音效用于当前游戏

用户在音频设置中选择一种游戏动作，生成并试听对应音效。满意后点击“应用到当前游戏”，在系统明确告知将替换哪一种声音时再次确认。系统把音频保存进当前项目并重新构建，下一次刷新 Web 试玩即可听到新声音。

### Acceptance Scenarios

1. 用户可从跳跃、金币、死亡、通关、踩中敌人和检查点六种用途选择一种，系统只把用途枚举交给主进程，不允许界面传入任意提示词。
2. 生成请求使用该用途对应的内置英文描述，返回结果明确标记用途，用户可以先试听。
3. 没有当前项目、没有生成结果或生成结果与当前选择不一致时，不能应用。
4. 用户点击应用后必须看到项目名称和将被替换的声音；取消时不写文件、不构建。
5. 确认后只把不超过 1 MiB 的有效 MP3 写到当前固定横版项目，并更新该项目的声音覆盖配置。
6. 写入后重新构建项目；构建失败时恢复应用前的配置和音频，原游戏继续可用。
7. 新建固定模板默认没有自定义覆盖，继续使用六个本地 WAV。
8. 当前 `星光森林` 保留森林美术、关卡和已验收内置音效，只增加读取覆盖配置的能力。

## Requirements

- **FR-001**: 生成入口必须提供六种固定用途，提示词由可信主进程映射。
- **FR-002**: 试听结果必须包含用途、模型、耗时和临时音频，不包含密钥、接口地址或提示词。
- **FR-003**: 应用操作必须使用强类型 IPC，并在主进程验证项目、用途、音频类型、大小和固定产品模式。
- **FR-004**: 应用前必须由用户进行最后确认。
- **FR-005**: 自定义 MP3 必须保存在项目 `public/assets/audio/custom/`，不得写到项目外部。
- **FR-006**: 项目必须使用受校验的 `src/audioOverrides.json` 决定是否覆盖单个声音；没有覆盖时使用原 WAV。
- **FR-007**: 应用后必须重新构建；失败必须回滚本次写入。
- **FR-008**: 不得增加任意文件上传、任意路径、自由提示词、批量替换或无人确认的自动应用。

## Success Criteria

- **SC-001**: 六种用途分别使用正确的固定描述，API 密钥不会进入 Renderer 或日志。
- **SC-002**: 路径越界、符号链接、非法 MP3、超大音频和非固定项目均被拒绝。
- **SC-003**: 确认、取消、成功写入和构建失败回滚测试通过。
- **SC-004**: 模板、当前 `星光森林` 和桌面端完整检查通过。

## Out of Scope

- 音效历史库、多个候选版本和批量替换。
- 用户上传任意音频文件。
- 背景音乐、语音、自由提示词和自动选择最佳音效。
- AI 在没有用户确认时直接修改项目。
