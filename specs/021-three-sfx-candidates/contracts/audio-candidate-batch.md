# Contract: 三候选音效批次

## Renderer → Preload

生成输入保持最小化：

- 固定声音用途。
- 1～300 字的临时声音描述。
- 0.5～8 秒半秒档位。
- 不接受候选数量、密钥、接口地址、路径或项目 ID。

## Preload → Main

- 单一强类型生成方法返回一个批次结果。
- Main 重新校验用途、描述和时长。
- Main 在全应用范围阻止重叠批次。
- Main 从安全存储读取音频服务凭据，并固定发起 3 次请求。

## Main Service → Renderer

成功批次只返回：

- 成功候选数组，每条含编号、用途、时长、模型、媒体类型、受限字节和耗时。
- 失败数量、固定尝试数量和批次耗时。

不得返回描述、密钥、接口地址、第三方错误正文或项目路径。

三条全部失败时返回统一、可重试的错误，不返回空的可应用批次。

## Renderer Selection → Existing Apply Flow

- Renderer 只允许从当前批次的成功候选中单选。
- 未选择时不调用应用方法。
- 选择后只传当前项目 ID、固定声音用途和所选候选字节。
- Main 继续显示系统确认框；取消时不修改项目。

## Usage Record

- 一次完整批次记录 `callCount: 3`。
- 全成功记为成功，部分成功记为警告，全部失败记为错误。
- 记录不得包含描述、密钥、接口地址、音频字节或项目路径。
