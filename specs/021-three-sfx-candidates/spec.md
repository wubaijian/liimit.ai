# Feature Specification: 三候选音效试听与选择

**Feature Branch**: `main`

**Created**: 2026-09-02

**Status**: Implemented

**Input**: 在已经支持自定义描述和时长选择的基础上，每次生成 3 条候选音效，让用户分别试听并明确选择其中一条，再确认应用到当前游戏。

## User Scenarios & Testing

### User Story 1 - 试听并选择三个候选音效 (Priority: P1)

游戏制作人员填写声音描述、选择用途和时长后，一次获得 3 条独立候选音效。他可以逐条试听、明确选择最满意的一条，然后再决定是否应用到当前游戏。

**Why this priority**: 同一句描述生成的声音可能有明显差异。一次提供 3 个选择，可以减少反复填写和生成的操作，同时把最终决定权留给用户。

**Independent Test**: 使用本地假结果完成一次生成，看到编号 1～3 的三张试听卡；选择第 2 条后只有第 2 条显示为已选，并且应用操作只携带第 2 条音频。

**Acceptance Scenarios**:

1. **Given** 用户已保存有效的音频服务设置并填写描述，**When** 点击生成，**Then** 页面明确说明本次会发起 3 次生成请求，额度消耗约为生成单条的 3 倍。
2. **Given** 三条候选全部生成成功，**When** 结果返回，**Then** 用户可以分别播放候选 1、候选 2 和候选 3。
3. **Given** 三条候选已经显示，**When** 用户选择候选 2，**Then** 候选 2 显示为已选择，其他候选保持未选择状态。
4. **Given** 用户没有选择候选，**When** 查看应用操作，**Then** 系统阻止应用并提示先选择一条。
5. **Given** 用户选择一条候选，**When** 点击应用并在系统确认框中确认，**Then** 只有所选候选被应用到当前游戏。
6. **Given** 三次生成中仅一条或两条成功，**When** 批次结束，**Then** 页面保留可试听的成功候选并明确显示失败数量，用户仍可选择成功候选。
7. **Given** 三次生成全部失败，**When** 批次结束，**Then** 页面不显示可选择候选，并给出可重试的错误说明。
8. **Given** 用户修改用途、描述或时长，**When** 输入发生变化，**Then** 旧的三条候选和选择状态全部清除，不修改已经应用到游戏的音效。

### Edge Cases

- 用户连续点击生成时，同一时刻最多只能有一个三候选生成批次。
- 每个成功候选必须来自同一组经过校验的用途、描述和时长。
- 部分失败时，成功候选保持原来的候选编号，不为凑齐三个而自动追加请求。
- 重新生成时立即释放旧候选的临时播放资源，避免内存持续占用。
- 关闭设置时释放所有候选的临时播放资源，且不保存候选或选择状态。
- 应用过程中不得切换候选、用途、描述或时长。

## Requirements

### Functional Requirements

- **FR-001**: 系统必须把一次用户生成操作固定为 3 条独立候选，并在生成前明确提示会发起 3 次生成请求，额度消耗约为单条的 3 倍。
- **FR-002**: 每条候选必须使用同一组已经校验的声音用途、描述和时长。
- **FR-003**: 系统必须为每个成功候选提供独立的编号、播放控件、时长和生成耗时信息。
- **FR-004**: 系统必须要求用户明确选择一条候选，不得在结果返回后自动替用户选择。
- **FR-005**: 任意时刻只能选择一条候选，并且界面必须清楚显示当前选择。
- **FR-006**: 未选择候选时不得应用音效；选择后只允许把所选候选交给现有确认应用流程。
- **FR-007**: 系统必须支持 1～2 条生成失败的情况，保留成功候选并显示失败数量；三条全部失败时不得显示可应用结果。
- **FR-008**: 系统必须阻止同一用户同时启动多个候选生成批次。
- **FR-009**: 修改用途、描述、时长、音频服务设置或关闭设置时，必须清除并释放全部临时候选和选择状态。
- **FR-010**: 生成结果和本机用量记录不得包含密钥、接口地址、用户描述或项目路径。
- **FR-011**: 本功能不得自动应用候选，不得绕过现有用户确认，不得把临时候选保存到项目或生成历史。

### Key Entities

- **候选生成批次**: 一次用户操作产生的最多 3 个候选结果，包含成功候选和失败数量。
- **候选音效**: 可单独试听的一条临时音频，具有固定编号、用途、时长、播放内容和生成耗时。
- **当前选择**: 用户在成功候选中明确选择的一条；输入变化或批次替换后失效。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 三条都成功时，用户一次生成后可以看到且分别播放 3 条候选。
- **SC-002**: 用户选择任意一条候选后，界面在 1 秒内只显示一个明确的已选状态。
- **SC-003**: 未选择候选时 100% 阻止应用；选择后 100% 只传递所选候选。
- **SC-004**: 1 条或 2 条失败时，所有成功候选仍可试听和选择；3 条全失败时没有可应用数据。
- **SC-005**: 连续点击不会产生重叠批次，单次用户操作最多发出 3 次外部生成请求。
- **SC-006**: 修改用途、描述或时长后，旧候选和选择状态在 1 秒内全部消失。
- **SC-007**: 现有单项恢复、项目确认应用、凭据保护和其他桌面功能继续通过完整回归检查。

## Assumptions

- 单次生成固定尝试 3 条候选，不提供 1 条、2 条或更多数量选择。
- 三条请求同时开始，以减少用户等待时间；每条仍沿用现有超时和大小限制。
- 候选差异由音效服务每次生成的自然随机性提供，不改写用户描述。
- 部分失败后不自动补发，以免产生用户没有预期的额外额度消耗。
- 用户可以只试听部分候选后做选择，但必须主动点击选择。

## Out of Scope

- 用户自定义候选数量。
- 用户取消正在进行的批次。
- 自动比较音效质量或由 AI 自动选出最佳候选。
- 保存候选历史、收藏候选或跨设置窗口恢复候选。
- 在应用前裁剪、混音、调节音量或编辑波形。
