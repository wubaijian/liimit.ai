# Feature Specification: 音效生成进度与主动停止

**Feature Branch**: `main`

**Created**: 2026-09-02

**Status**: Implemented

**Input**: 在三候选音效生成过程中显示已完成、成功和失败数量，并允许用户主动停止本次生成；停止后不展示、不保存、不应用本批候选。

## User Scenarios & Testing

### User Story 1 - 查看三候选生成进度 (Priority: P1)

游戏制作人员启动三候选生成后，可以持续看到本批次总数、已完成数量、成功数量和失败数量，知道系统仍在工作而不是卡住。

**Why this priority**: 三条音效可能需要等待数十秒。清楚的进度可以降低“页面没反应”的误解，也是安全停止操作的基础。

**Independent Test**: 使用三个可控制结束顺序的本地假请求，依次完成一条成功、一条失败、一条成功；界面进度依次显示 1/3、2/3、3/3，成功和失败数量准确。

**Acceptance Scenarios**:

1. **Given** 用户点击生成三条候选，**When** 批次开始，**Then** 页面立即显示“已完成 0/3、成功 0、失败 0”。
2. **Given** 第一条请求成功，**When** 其余两条仍在生成，**Then** 页面更新为“已完成 1/3、成功 1、失败 0”。
3. **Given** 第二条请求失败，**When** 第三条仍在生成，**Then** 页面更新为“已完成 2/3、成功 1、失败 1”。
4. **Given** 三条请求全部结束，**When** 批次返回，**Then** 进度显示完成，并继续进入现有候选试听与选择流程。

---

### User Story 2 - 主动停止正在生成的批次 (Priority: P1)

游戏制作人员不想继续等待时，可以点击“停止生成”。系统停止仍在进行的请求，清除本批次所有临时结果，并保留用途、描述和时长，方便重新调整或重试。

**Why this priority**: 用户必须能够控制可能持续较长时间和产生外部额度消耗的操作，不能只能等待超时。

**Independent Test**: 使用三个不会自行结束的本地假请求启动批次，点击停止后确认三个请求收到停止信号、生成调用结束、页面没有候选、输入保持原样并显示“已停止”。

**Acceptance Scenarios**:

1. **Given** 三候选正在生成，**When** 用户点击“停止生成”，**Then** 按钮立即变为“正在停止”，防止重复点击。
2. **Given** 一条候选已经成功、两条仍在生成，**When** 用户点击停止，**Then** 整个批次作废，已经成功的临时结果也不展示、不保存、不应用。
3. **Given** 用户发出停止后，**When** 服务刚好同时完成，**Then** 用户的停止意图优先，Renderer 丢弃迟到结果。
4. **Given** 批次已停止，**When** 用户查看表单，**Then** 用途、描述和时长保持不变，可以再次点击生成。
5. **Given** 当前没有生成任务，**When** 发生重复或迟到的停止请求，**Then** 系统安全返回“当前无需停止”，不影响下一次生成。

### Edge Cases

- 进度事件只能属于当前音效生成批次，旧批次事件不得覆盖新批次状态。
- 停止只影响当前音效候选批次，不停止 Agent、试玩、构建或其他功能。
- 停止后不得承诺退还已经产生的第三方额度；界面必须说明已经完成的请求可能已经计费。
- 关闭设置窗口时，如果仍在生成，只释放 Renderer 状态；不得自动发送未经用户触发的停止操作。
- 网络超时仍按失败处理，不冒充用户主动停止。
- 生成完成后停止按钮必须消失，避免用户误以为还能撤销已经产生的额度。

## Requirements

### Functional Requirements

- **FR-001**: 批次开始后必须显示固定总数 3，以及已完成、成功、失败数量。
- **FR-002**: 每条候选成功或失败后，进度必须更新一次，且始终满足“已完成 = 成功 + 失败”。
- **FR-003**: 进度数据必须由可信生成流程产生，界面不得自行推测请求是否完成。
- **FR-004**: 生成期间必须显示“停止生成”按钮，并在停止请求发出后进入不可重复点击的“正在停止”状态。
- **FR-005**: 停止操作必须中断当前批次中尚未完成的外部请求，并结束当前生成调用。
- **FR-006**: 用户停止后，本批全部候选必须作废，包括停止前已经完成的候选。
- **FR-007**: 用户停止或迟到结果返回后不得自动应用、保存或展示本批候选。
- **FR-008**: 停止后必须保留当前用途、描述和时长，并允许用户重新生成。
- **FR-009**: 没有活动批次时的停止请求必须安全无副作用。
- **FR-010**: 进度和停止通道不得传递密钥、接口地址、声音描述、音频字节、项目 ID 或路径。
- **FR-011**: 进度事件必须带批次标识；Renderer 只接受当前批次事件，防止迟到事件污染状态。
- **FR-012**: 本功能不得声称停止能够退还已经完成请求产生的第三方额度。

### Key Entities

- **生成进度**: 当前批次的标识、状态、总数、已完成数、成功数和失败数。
- **停止请求**: 用户对当前唯一音效批次发出的控制操作，结果为“正在停止”或“当前空闲”。
- **作废批次**: 用户已经停止的批次；其任何成功结果都不得进入候选展示与应用流程。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 每条请求结束后 1 秒内，页面显示正确的已完成、成功和失败数量。
- **SC-002**: 生成期间用户可以用一次点击发出停止，按钮立即进入不可重复点击状态。
- **SC-003**: 本地可控请求测试中，停止后 100% 的未完成请求收到停止信号。
- **SC-004**: 在“已成功 1 条后停止”和“完成与停止同时发生”两种竞态下，页面均不出现本批候选。
- **SC-005**: 停止后用途、描述和时长 100% 保留，用户可以直接重试。
- **SC-006**: 进度与停止数据中不存在密钥、接口地址、描述、音频字节、项目或路径字段。
- **SC-007**: 三候选、试听、单选、确认应用、恢复内置音效和其他桌面功能继续通过完整回归检查。

## Assumptions

- 同一时间仍然只有一个音效候选批次，因此停止操作只需要控制当前批次。
- 停止按钮不提供暂停和继续；停止后若要重试会创建全新批次。
- 已经到达第三方并完成的请求可能已经产生额度消耗，产品只能停止未完成部分。
- 关闭设置不自动停止，避免把普通关闭窗口变成隐藏的外部控制副作用。

## Out of Scope

- 暂停后继续生成。
- 单独停止某一条候选。
- 停止 Agent、游戏构建、试玩或其他任务。
- 额度退款、精确费用结算或服务商账单同步。
- 保存进度历史或恢复已停止批次。
