# Feature Specification: 候选音效单条试听控制

**Feature Branch**: `main`

**Created**: 2026-09-02

**Status**: Implemented

**Input**: 三候选音效只能同时播放一条；播放新候选时停止并重置上一条，同时支持当前候选暂停、继续和从头重新播放。

## User Scenarios & Testing

### User Story 1 - 清楚试听一条候选 (Priority: P1)

游戏制作人员试听多个候选时，系统保证同一时间只有一条发声。用户播放另一条候选后，上一条立即停止并回到开头，避免声音重叠影响判断。

**Why this priority**: 三条音效同时发声会让用户无法分辨候选质量，也可能误以为音频损坏。

**Independent Test**: 使用三个本地假播放器，先播放候选 1，再播放候选 2；候选 1 被暂停并回到 0 秒，候选 2 保持播放，候选 3 不受影响。

**Acceptance Scenarios**:

1. **Given** 候选 1 正在播放，**When** 用户播放候选 2，**Then** 候选 1 立即停止并回到开头，只有候选 2 发声。
2. **Given** 当前候选正在播放，**When** 用户点击原生暂停，**Then** 当前候选暂停并保留位置，再次播放时从暂停位置继续。
3. **Given** 任一候选已经播放一部分或播放结束，**When** 用户点击“从头播放”，**Then** 其他候选停止，该候选从 0 秒开始播放。
4. **Given** 候选正在播放，**When** 用户重新生成、修改输入、切换服务或关闭设置，**Then** 候选停止且临时播放资源按现有规则释放。

### Edge Cases

- 用户快速交替点击多个播放按钮时，最终只能保留最后触发播放的候选。
- 浏览器拒绝播放时，不得影响候选选择、应用或其他游戏功能。
- 候选因批次替换而移除时，对应播放器必须从控制集合中删除。
- 播放互斥只作用于当前音效候选，不暂停游戏试玩、系统音频或其他应用。

## Requirements

### Functional Requirements

- **FR-001**: 同一批候选中任意时刻最多只能有一条候选音效播放。
- **FR-002**: 新候选开始播放时，其他候选必须暂停并把播放位置重置为 0。
- **FR-003**: 用户在当前候选上使用原生暂停和继续时，系统必须保留该候选的暂停位置。
- **FR-004**: 每条候选必须提供明确的“从头播放”操作。
- **FR-005**: 从头播放必须先停止其他候选，再把目标候选定位到 0 秒并开始播放。
- **FR-006**: 候选移除、批次替换或设置关闭时必须停止并释放对应临时播放资源。
- **FR-007**: 播放失败不得修改候选选择、当前项目或已应用音效。
- **FR-008**: 本功能不得发起新的音效生成请求，不得读取或写入 API 凭据。

### Key Entities

- **候选播放器集合**: 当前设置窗口内候选编号与音频播放器的临时对应关系。
- **当前播放候选**: 最近成功进入播放状态的候选编号；暂停、结束或移除后为空。
- **重新播放操作**: 用户明确要求目标候选从头开始播放的本地操作。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 本地三播放器测试中，切换候选后正在发声的播放器数量始终不超过 1。
- **SC-002**: 100% 的被替换播放器都会收到暂停并重置到 0 秒。
- **SC-003**: 从头播放目标候选时，目标位置为 0 秒且只调用一次播放。
- **SC-004**: 原有三候选、选择、应用、恢复、进度和停止功能继续通过完整回归。
- **SC-005**: 实现和验收过程中不产生任何 ElevenLabs 生成调用或额度消耗。

## Assumptions

- 暂停和继续继续使用浏览器原生音频控件，不重复制作一套自定义播放器。
- “播放新候选时停止上一条”表示上一条回到开头；用户回去播放时从头开始。
- 音频播放状态只存在于当前设置窗口，不保存到项目。

## Out of Scope

- 同时混音或比较两条候选。
- 音量标准化、波形裁剪和淡入淡出。
- 全局系统音量控制。
- 生成新候选或补生成失败候选。
