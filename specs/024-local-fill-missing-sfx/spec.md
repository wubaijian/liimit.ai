# Feature Specification: 本地补齐缺少的音效候选

**Created**: 2026-09-02

**Status**: Draft

## User Story - 不消耗 API 地补齐候选 (P1)

当三次外部生成只有一条或两条成功时，用户可以明确点击“本地补齐”。系统只为缺少的编号生成本地 WAV 备用音效，不再次请求外部服务，并允许用户像普通候选一样试听、选择和应用。

### Acceptance Scenarios

1. 缺1条时只本地生成1条，并保留原有2条。
2. 缺2条时只本地生成2条，并保留原有1条。
3. 本地补齐不读取密钥、不发网络请求、不增加 API 用量记录。
4. 页面清楚区分“ElevenLabs 候选”和“本地备用候选”。
5. 本地 WAV 候选可以试听、单选、确认应用并在游戏中作为 WAV 加载。
6. 本地生成失败时保留原有成功候选和输入，不修改项目。

## Requirements

- **FR-001**: 只能补齐候选编号 1、2、3 中当前缺少的编号。
- **FR-002**: 补齐数量必须等于当前失败数量，最多2条。
- **FR-003**: 本地音效必须是 44.1kHz、16位、单声道、可验证的 WAV，时长与用户选择一致，且不超过1MiB。
- **FR-004**: 本地生成必须按声音用途和候选编号产生可听差异。
- **FR-005**: 本地生成不得使用 `fetch`、IPC生成接口、API Key或外部程序。
- **FR-006**: 本地候选必须标注来源，并与外部候选共同按编号排序。
- **FR-007**: 应用链路必须同时安全支持 MP3 和 WAV，并继续执行用户确认、目录限制、原子写入、构建和失败回滚。
- **FR-008**: 已存在的 MP3 自定义音效配置必须继续可读。
- **FR-009**: 本功能不自动补齐，必须由用户点击触发。

## Success Criteria

- 本地测试中缺1补1、缺2补2准确率100%。
- 生成的 WAV 头、长度、时长和峰值检查100%通过。
- 本地补齐代码中不存在联网和凭据入口。
- 现有音效、项目和完整桌面回归继续通过。

## Out of Scope

- 用本地生成器理解自然语言描述的全部语义。
- 本地生成背景音乐、配音或长音频。
- 自动替用户选择或应用候选。
