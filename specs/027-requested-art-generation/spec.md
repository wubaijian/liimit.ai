# Feature Specification: 用户请求美术生成与真实修改状态

**Created**: 2026-09-14
**Status**: Approved for implementation
**Input**: 用户同意放开明确请求的图片生成，并修正未修改却报告完成。

## User Scenarios & Testing

### User Story 1 - 请求换画风 (P1)

用户要求海底背景和海豚主角时，助手可以使用已配置图片服务生成和接入指定素材。
验收：明确请求时规则允许生成；只改关卡时不生成图片；失败保留原素材并说明原因。

### User Story 2 - 真实结果 (P1)

助手只阅读或拒绝操作时，用户看到本轮没有产生游戏文件修改，而不是游戏生成完成。
验收：内容不变或无法核验时进入待继续状态；内容变化后仍须构建验证。

### Edge Cases

缺少图片配置、只支持文字的模型、旧会话限制、生成失败、仅时间戳变化、文件删除、符号链接。

## Requirements

- FR-001: 明确请求换画风允许生成指定图片；默认仍复用素材。
- FR-002: 要求素材生成、引用接入、验证和结果说明，失败不得假称完成。
- FR-003: 本轮无游戏文件内容变化时不得报告游戏生成完成。
- FR-004: 不更改用户凭据，不自动发起付费生成。

## Success Criteria

- SC-001: 规则测试覆盖请求生成、默认复用、失败保留和接入验证。
- SC-002: 不变、修改、删除、时间戳变化的本地检查均得到正确结果。

## Assumptions

复用现有素材工具；本次验收使用本地测试，不代表服务商图片能力已验证。
