# Feature Specification: 创建后按要求自动生成

**Created**: 2026-09-17
**Status**: Approved
**Input**: 用户确认修复创建流程；本次交付第一部分，结果逐项核对为后续部分。

## User Scenarios & Testing

### User Story 1 - 创建即执行 (P1)

用户选择 AI 生成并提交要求后，不需要再次启动助手。固定模板不使用 AI。
验收：相同要求分别以两种模式创建，AI 模式准备完成后执行一次原要求，模板模式执行零次。缺少配置或已有任务时明确阻止启动。

### User Story 2 - 看清状态并安全重试 (P1)

用户能分清基础模板、生成中、未完成、运行检查通过；可停止、手动重试，重开应用不偷偷执行。
验收：准备失败、启动失败、停止、重启、无文件变化都不显示 AI 制作完成。原始要求保留；旧项目不自动生成。

### Edge Cases

重复提交、准备中切换项目、准备中退出、准备与手动执行竞争、失败后重试、模板准备成功但模型未改文件。

## Requirements

- FR-001：区分固定模板与 AI 创建；旧项目和未指定模式默认模板。
- FR-002：AI 创建按钮明确告知使用已配置服务；提交一次后准备基础游戏，再自动执行输入要求一次；准备失败不得执行。
- FR-003：首次创建授权仅限本次新项目；现有项目修改仍保留原确认规则。
- FR-004：显示准备、生成和未完成状态；仅文件实际更新且运行检查通过后标记完成，不承诺所有要求已经满足。
- FR-005：停止或退出后不得自动重试；保留要求和已有文件，允许用户主动继续；同一时间只允许一个 AI 工作流。
- FR-006：不改旧项目、不泄露凭据，验证不调用真实付费模型；接口及状态变更有兼容测试。

## Key Entities

创建方式；首次生成状态（待准备、执行中、未完成、已完成）；项目原有状态与准备进度。

## Success Criteria

- SC-001：自动化验收中 AI 创建只执行一次，模板创建零次。
- SC-002：准备失败、停止、重启和重复启动用例均无意外生成或虚假完成。
- SC-003：用户创建后无需第二次点击启动，即可看到生成进度；旧项目照常打开。

## Assumptions

保留固定横版范围和现有模型运行、超时、文件检查机制；本次不增加模型能力，不实现逐条需求评分和新素材服务。应用重启需要用户主动继续，不后台排队消耗费用。
