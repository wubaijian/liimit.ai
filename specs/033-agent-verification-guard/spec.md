# Feature Specification: AI 验证流程与失败止损

**Created**: 2026-09-17
**Status**: Approved
**Input**: 用户确认修复越界临时文件、错误试玩检查、反复失败与进度说明。

## User Scenarios & Testing

### US1 — 正确检查游戏（P1）

用户生成或继续修改游戏后，助手只在当前项目内准备辅助检查，不另开不匹配的试玩服务；平台负责正式入口核验。
独立验收：新任务和恢复任务都得到相同规则；正式入口的数据真实有效，错误网页不能算关卡数据。

### US2 — 失败及时停下（P1）

用户看到具体失败原因和已有内容保留说明；重复失败或构建后长时间不收尾自动停止，不把未验证的内容称为完成。
独立验收：同类错误第三次触发停止，构建成功后超过五分钟未收尾触发停止；正常结果不误判。用户可明确启动下一轮，无自动重试。

### Edge Cases

恢复旧会话、重复事件、成功读取夹在失败之间、命令输出含报错但工具标志为成功、用户停止与自动停止竞态、图片生成长任务、JSON 入口实际返回 HTML。

## Requirements

- FR-001：每次启动/恢复注入项目内辅助文件和正式试玩流程指引；不得建议绕过权限或读取应用安装目录。
- FR-002：正式试玩入口核验覆盖页面、脚本、关卡与游戏信息，不把仅构建通过描述为通关验证。
- FR-003：同轮同类工具错误第三次自动停止，普通成功读取不得清空错误计数；同一结果不得重复计数。明确的命令失败即使工具未标错也须识别。
- FR-004：构建成功后五分钟仍未收尾且无素材生成在途时停止验证循环；不因思考/读取日志持续输出而无限延长。
- FR-005：中文说明失败类别、停止原因和文件/会话保留；自动停止不标记已完成，不自动恢复或调用收费服务。
- FR-006：兼容旧项目和停止/恢复/超时机制，测试只用假运行时与临时项目，不改用户关卡、不调用用户 API。

## Key Entities

本轮失败计数、去重结果标识、构建成功时刻、自动停止原因；仅内存持有，不改变存储格式。

## Success Criteria

- SC-001：三次同类错误及五分钟验证上限都有可复现自动测试，并保留明确的非完成状态。
- SC-002：正式入口错误数据不能通过核验；正常生成和用户取消回归通过。
- SC-003：交付列明实际验证与未验证项目，不将入口检查当作实际玩通。

## Assumptions

现有文件权限继续保留；指引不构成新的系统级沙箱。自动停止保留已写入内容但不承诺内容有效。无需本次重做已生成关卡。五分钟为构建后的检查预算，不是整个生成耗时上限。
