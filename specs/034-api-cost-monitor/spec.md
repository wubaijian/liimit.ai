# Feature Specification: API 费用监测与预算保护

**Feature Branch**: `034-api-cost-monitor`
**Created**: 2026-09-17
**Status**: Approved for implementation
**Input**: 用户确认增加 API 调用费用监测，防止重复报错造成损失；测试不调用付费 API。

## User Scenarios & Testing

### User Story 1 - 看懂费用 (Priority: P1)

用户在 AI 助手内看到本次任务、项目累计、文本/图片/音效分类、调用及失败次数。
**Why this priority**: 暂停和出错不应漏记。
**Independent Test**: 本机假服务提供用量，持久化后重开仍可查看。
**Acceptance Scenarios**:

1. 请求发出前建立记录；完成、失败、暂停均结算，未知不写零。
2. 旧记录不伪装成完整账单；价格按请求时快照，变更不回算历史。

### User Story 2 - 限制继续消费 (Priority: P1)

用户自行设置人民币预算和模型单价；80%提醒，达到预算不再发起新调用。
**Why this priority**: 监测必须能够制止循环。
**Independent Test**: 假服务达到预算后收到的请求数不再增加。
**Acceptance Scenarios**:

1. 开启预算但缺价格时拒绝付费请求；用量缺失或中断则暂停，不把未知当免费。
2. 请求逐个放行，最多一笔在途；在途费用可能越过预算，账单以服务商为准。
3. 默认最多20次请求、连续3次网络/接口失败停止；保留已有游戏，用户手动继续才新开任务。

### User Story 3 - 设置与安全 (Priority: P2)

模型换了就重新核对价格；重复素材生成须确认，记录只留计费元信息。
**Independent Test**: IPC输入非法值被拒；本地假服务验证取消、重启、密钥不落日志。
**Acceptance Scenarios**:

1. 价格绑定槽位、服务商、模型和地址指纹；UI不暴露凭据。
2. 同任务第二次及以后素材生成先确认；拒绝不产生上游请求。
3. 主模型、推理、素材配置的请求接入统一监测；设置音效试听也监测。

### Edge Cases

流式用量分包、缺用量、缓存用量、模型覆写、取消、崩溃未结算、价格缺失、并发请求、存储失败、重定向、未知接口和重复素材请求。插件/MCP或自定义脚本直连的第三方费用不在覆盖范围；连接测试单列现有调用统计，不计入游戏任务预算。

## Requirements

### Functional Requirements

- **FR-001**: 请求级本地记录与分类汇总，不依赖最终结果事件。
- **FR-002**: 按明确填写的人民币单价估算；文本含缓存单价，素材每请求参考价，未知显式展示。
- **FR-003**: 预算80%提醒/100%阻止后续请求；未知费用时预算模式暂停；默认20次和连续3错保护。
- **FR-004**: 暂停取消在途连接，重启不重放，保留消费记录和已有游戏。
- **FR-005**: AI助手紧凑面板、展开价格与预算、停止后可查摘要；实时更新不自动开始调用。
- **FR-006**: 强类型可信IPC、输入约束、无密钥/提示词/URL记录；仅本机可访问、路由固定的请求监测器。
- **FR-007**: 重复素材确认与音效试听纳入监测；额外插件/直连脚本/连接测试明确边界。
- **FR-008**: 零付费测试、兼容旧数据、完成桌面检查和打包验证。

### Key Entities

- 价格配置：槽位/模型/提供方/地址指纹、输入输出缓存每百万单价或素材每次参考金额。
- 任务：项目、预算快照、状态、开始/结束、次数限制。
- 请求：任务、槽位、模型、价格快照、状态、用量、估算金额或未知。

## Success Criteria

- **SC-001**: 假服务预算达到后无下一笔上游请求；连续3错/20次同理。
- **SC-002**: 暂停、缺用量和重启的记录不被显示为免费；非法输入/重定向/越界路由无上游请求。
- **SC-003**: 用户在助手内直接查看金额和展开设置，无需翻阅完整事件记录。

## Assumptions

价格未提供，不预填虚构值；默认仅监测并有次数保护，人民币预算须用户填写才启用。估算非真实账单，单笔在途可超预算。不追溯恢复历史完整消费。不修改现有游戏内容，不自动续跑。不支持的计费形式标为未知并在预算模式拒绝继续。
